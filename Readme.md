# Booking

Учебный проект: HTTP API для бронирования ресурсов (ASP.NET Core Minimal API).

Данные хранятся в памяти процесса и теряются при перезапуске. Авторизации нет: любой клиент может выполнить любую операцию над любой сущностью.

## Сущности

### Пользователь (`User`)

| Поле | Правило |
| --- | --- |
| `Id` | Генерируется сервером (GUID v7). |
| `Name` | Обязательное, не пустое и не из одних пробелов. |

### Ресурс (`Resource`)

То, что бронируют. После создания не изменяется.

| Поле | Правило |
| --- | --- |
| `Id` | Генерируется сервером (GUID v7). |
| `ResourceType` | `Master` (мастер) или `Property` (объект недвижимости). |
| `Title`, `Description` | Обязательные, не пустые. |
| `UserId` | Владелец ресурса. Не может быть пустым GUID. |
| `CancellationWindowInHours` | Окно отмены, в часах. Необязательное. |
| `RescheduleWindowInHours` | Окно переноса, в часах. Необязательное. |

Окно — это минимальное число часов до начала брони, когда её ещё можно отменить или перенести.

- Допустимые значения окна: от `0` до `8760` (365 дней) включительно.
- Если окно не передано, берётся значение по умолчанию для типа ресурса:

| Тип | Окно по умолчанию |
| --- | --- |
| `Master` | 24 часа |
| `Property` | 48 часов |

### Бронь (`BookingEntity`)

| Поле | Правило |
| --- | --- |
| `Id` | Генерируется сервером (GUID v7). |
| `ResourceId` | Какой ресурс бронируется. Не может быть пустым GUID. |
| `UserId` | Кто бронирует. Не может быть пустым GUID. |
| `From`, `To` | Интервал брони. `From` строго раньше `To`. |
| `StateType` | Текущее состояние, см. ниже. |

## Состояния брони

Новая бронь создаётся в состоянии `Pending`.

| Состояние | Что означает | Как возникает |
| --- | --- | --- |
| `Pending` | Ожидает подтверждения. | При создании и после переноса. |
| `Confirmed` | Подтверждена. | Операция подтверждения. |
| `Canceled` | Отменена. | Операция отмены. |
| `Expired` | Не была подтверждена до начала. | Автоматически: бронь `Pending`, а текущее время позже `From`. |
| `Completed` | Состоялась. | Автоматически: бронь `Confirmed`, а текущее время позже `To`. |

`Expired` и `Completed` не сохраняются, а вычисляются по текущему времени при каждом чтении. Подтверждённая бронь между `From` и `To` остаётся `Confirmed`.

**Активная** бронь — это `Pending` или `Confirmed`. Только активные брони занимают время ресурса и могут быть отменены или перенесены.

```
            подтверждение                 now > To
 Pending ─────────────────► Confirmed ─────────────► Completed
    │  ▲                       │  │
    │  └───────────────────────┘  │
    │          перенос            │
    │                             │
    ├── now > From ──► Expired    │
    │                             │
    └────────── отмена ───────────┴──► Canceled
```

## Правила операций

Текущее время всегда берётся в UTC.

### Создание брони

1. `ResourceId` и `UserId` не пустые.
2. `From` строго раньше `To`.
3. `From` не в прошлом.
4. Интервал не пересекается с другой активной бронью того же ресурса.

Пересечение считается по полуоткрытым интервалам: бронь, которая начинается ровно в момент окончания другой, конфликтом не является.

### Подтверждение

Подтвердить можно только бронь в состоянии `Pending`. Просроченную (`Expired`) подтвердить нельзя.

### Отмена

1. Бронь активна.
2. До начала брони осталось не меньше окна отмены ресурса: `From >= now + CancellationWindowInHours`.

Из второго правила следует, что уже начавшуюся бронь отменить нельзя, даже при окне `0`.

### Перенос

1. Новый интервал корректен: `From` строго раньше `To`.
2. Новый интервал не пересекается с другими активными бронями того же ресурса (сама переносимая бронь не учитывается).
3. Новый `From` не в прошлом.
4. Бронь активна.
5. До **текущего** начала брони осталось не меньше окна переноса ресурса: `From >= now + RescheduleWindowInHours`.

После переноса бронь возвращается в `Pending` и требует повторного подтверждения, даже если была `Confirmed`.

### Защита от двойного бронирования

Создание, подтверждение, отмена и перенос выполняются строго по очереди под одной общей блокировкой. Два одновременных запроса на одно и то же время не могут пройти оба: второй получит конфликт.

## API

Базовый путь — `/api`. Перечисления передаются строками (`"Master"`, `"Pending"`).

### Пользователи

| Метод | Путь | Тело | Успех |
| --- | --- | --- | --- |
| `POST` | `/users` | `name` | `201`, `{ id }` |
| `GET` | `/users/{id}` | — | `200`, пользователь |

### Ресурсы

| Метод | Путь | Тело / параметры | Успех |
| --- | --- | --- | --- |
| `POST` | `/resources` | `resourceType`, `title`, `description`, `userId`, `cancellationWindowInHours?`, `rescheduleWindowInHours?` | `201`, `{ id }` |
| `GET` | `/resources/{id}` | — | `200`, ресурс |
| `GET` | `/resources/list` | `userId?` — только ресурсы этого владельца | `200`, список |

### Брони

| Метод | Путь | Тело / параметры | Успех |
| --- | --- | --- | --- |
| `POST` | `/bookings` | `resourceId`, `userId`, `from`, `to` | `201`, `{ id }` |
| `PATCH` | `/bookings/confirm` | `id` | `204` |
| `PATCH` | `/bookings/cancel` | `id` | `204` |
| `PATCH` | `/bookings/reschedule` | `id`, `from`, `to` | `204` |
| `GET` | `/bookings/{id}` | — | `200`, бронь |
| `GET` | `/bookings/list` | фильтры, см. ниже | `200`, список |

Фильтры списка броней необязательны и объединяются по «И»:

| Параметр | Что отбирает |
| --- | --- |
| `resourceId` | Брони этого ресурса. |
| `userId` | Брони этого пользователя. |
| `from` | Брони, которые заканчиваются не раньше этого момента. |
| `to` | Брони, которые начинаются не позже этого момента. |
| `inStateType` | Брони в одном из перечисленных состояний (с учётом вычисляемых `Expired` и `Completed`). |

`from` и `to` вместе отбирают брони, пересекающиеся с периодом; границы включаются.

### Коды ошибок

| Код | Когда |
| --- | --- |
| `400` | Некорректные данные: пустое имя, пустой GUID, `From >= To`, начало в прошлом, окно вне диапазона, неизвестный тип ресурса. |
| `404` | Сущность не найдена. При отмене и переносе — также если не найден ресурс брони. |
| `409` | Нарушено бизнес-правило: пересечение с другой бронью, неподходящее состояние, окно отмены или переноса уже прошло. |

## Что сейчас не проверяется

- При создании брони не проверяется, что ресурс и пользователь существуют. Бронь на несуществующий ресурс создаётся, но отменить или перенести её нельзя (`404`).
- При создании ресурса не проверяется, что владелец существует.
- Не проверяется, кто выполняет операцию: подтвердить, отменить или перенести бронь может кто угодно.
